P5. Comparaison GLM contre gradient boosting

Cette fiche illustre la démarche B (construire un modèle) avec un challenger ML. Ce que vous apprenez n’est pas le gradient boosting, mais comment cadrer un benchmark défendable (split train/test, métrique commune) et comment résister au biais du LLM qui privilégie spontanément le ML pour la performance brute au détriment de la défendabilité réglementaire.

TipDémarche illustrée : B, construire un modèle (avec arbitrage méthodologique)

La démarche se pratique en direct dans l’atelier de la demi-journée « Exploration et modélisation » du support.

Le contexte métier

Le pricing utilise de plus en plus des modèles de gradient boosting (XGBoost, LightGBM) en challenger des GLM. La question récurrente : lequel choisir, dans quel contexte ?

La réponse n’est pas que de la performance prédictive. Trois axes structurent le choix : qualité prédictive hors échantillon, interprétabilité, défendabilité en revue tarifaire. Le GLM l’emporte en général sur les deux derniers ; sur le premier, l’écart se mesure, il ne se présume pas, et il dépend de ce que le GLM a oublié. La décision finale dépend aussi de la culture de l’organisme et de qui validera le tarif.

Ce cas fait le benchmark, montre comment lire l’écart, et propose un cadre de décision argumenté.

Donnée d’entrée

On reprend le portefeuille commun aux fiches P1 à P5 (50 000 polices, même simulation, même graine) et le découpage de P2. La simulation contient un effet que le GLM de P2 ne déclare pas : une fréquence plus forte pour un conducteur de 25 ans ou moins au volant d’un véhicule puissant. On le sait parce qu’on a écrit la simulation ; sur un vrai portefeuille, on ne le saurait pas, et c’est tout l’intérêt du challenger.

import numpy as np
import pandas as pd
import matplotlib.pyplot as plt

rng = np.random.default_rng(42)
N = 50_000  # le vrai freMTPL2freq compte 678 013 lignes

age = rng.integers(18, 86, size=N)
puissance = rng.integers(4, 12, size=N)
zone = rng.choice(list("ABCDEF"), size=N, p=[0.12, 0.12, 0.22, 0.24, 0.20, 0.10])  # A rural, F urbain dense
# 60 % des contrats présents toute l'année, les autres entrés ou sortis en cours d'année
exposure = np.where(rng.random(N) < 0.6, 1.0, rng.uniform(0.05, 1.0, size=N)).round(3)

# Risque propre au conducteur, que le tarif ne voit pas (moyenne 1). Il fait les
# sinistres passés, donc le bonus-malus, et les sinistres de l'année : c'est par lui
# que le bonus-malus prédit la fréquence.
risque_cache = rng.gamma(shape=2.0, scale=0.5, size=N)
sinistres_passes = rng.poisson(0.25 * risque_cache)
# Bonus-malus à la française (clause type de l'article A121-1 du Code des assurances) :
# 100 au permis, 0,95 par an sans sinistre responsable, plancher 50, 1,25 par
# sinistre responsable, plafond 350.
plancher = np.maximum(50, 100 * 0.95 ** (age - 18))
bonus_malus = np.minimum(350, np.round(plancher * 1.25 ** sinistres_passes)).astype(int)

# Fréquence annuelle : en U selon l'âge (jeunes conducteurs les plus risqués, remontée
# après 70 ans), croissante avec la densité, un peu avec la puissance, et plus forte
# pour un conducteur de 25 ans ou moins au volant d'un véhicule puissant.
effet_zone = pd.Series(zone).map({"A": -0.30, "B": -0.15, "C": 0.0,
                                  "D": 0.10, "E": 0.25, "F": 0.40}).to_numpy()
log_freq = (np.log(0.07)
            + 1.1 * np.exp(-(age - 18) / 6)
            + 0.03 * np.maximum(age - 70, 0)
            + 0.03 * (puissance - 6)
            + 0.5 * ((age <= 25) & (puissance >= 9))
            + effet_zone
            + np.log(risque_cache))
nb_sinistres = rng.poisson(np.exp(log_freq) * exposure)

polices = pd.DataFrame({
    "age": age,
    "bonus_malus": bonus_malus,
    "puissance": puissance,
    "zone": zone,
    "exposure": exposure,
    "nb_sinistres": nb_sinistres,
})
print(f"Polices : {len(polices):,}")
print(f"Sinistres : {polices['nb_sinistres'].sum():,}")
print(f"Fréquence moyenne : {polices['nb_sinistres'].sum() / polices['exposure'].sum():.4f}")
Polices : 50,000
Sinistres : 4,014
Fréquence moyenne : 0.0989

Étape 2. La référence : le GLM Poisson de P2

import statsmodels.api as sm
import statsmodels.formula.api as smf

formule = ("nb_sinistres ~ C(age_bande, Treatment('31-45')) + C(bm_bande, Treatment('50'))"
           " + puissance + C(zone)")
glm = smf.glm(formule, data=app, family=sm.families.Poisson(),
              offset=np.log(app["exposure"])).fit()
for d in (app, tst):
    d["freq_glm"] = glm.predict(d, offset=np.zeros(len(d)))

def contributions(y, mu):
    """Déviance de Poisson police par police ; mu = nombre de sinistres attendu."""
    return 2 * (np.where(y > 0, y * np.log(np.where(y > 0, y, 1) / mu), 0) - (y - mu))

def deviance_poisson(y, mu):
    return contributions(y, mu).sum()

def gini(d, col):
    d = d.sort_values(col)
    x = np.r_[0, d["exposure"].cumsum() / d["exposure"].sum()]
    z = np.r_[0, d["nb_sinistres"].cumsum() / d["nb_sinistres"].sum()]
    return 1 - 2 * np.sum(np.diff(x) * (z[1:] + z[:-1]) / 2)

y_tst, e_tst = tst["nb_sinistres"].to_numpy(), tst["exposure"].to_numpy()
freq_app = app["nb_sinistres"].sum() / app["exposure"].sum()
dev_uniforme = deviance_poisson(y_tst, freq_app * e_tst)
dev_glm = deviance_poisson(y_tst, tst["freq_glm"].to_numpy() * e_tst)
print(f"Déviance de test : tarif uniforme {dev_uniforme:,.1f}, GLM {dev_glm:,.1f}")
print(f"Gini de test du GLM : {gini(tst, 'freq_glm'):.3f}")
Déviance de test : tarif uniforme 6,187.5, GLM 5,929.2
Gini de test du GLM : 0.239

Le GLM de P2 ramène la déviance de test de 6 187,5 (tarif uniforme) à 5 929,2, avec un Gini de 0,239 : les chiffres de P2, puisque c’est le même modèle sur le même découpage. La déviance est finie : avec un lien log, un GLM ne prédit jamais une fréquence nulle.

Étape 3. Le challenger : un gradient boosting à perte de Poisson

xgboost ne fait pas partie des dépendances de la formation (requirements.txt). Le corrigé exécuté utilise donc HistGradientBoostingRegressor de scikit-learn, un gradient boosting sur histogrammes de la même famille, avec une perte de Poisson. Il ne prend pas d’offset : on lui donne la fréquence (sinistres / exposition) en cible et l’exposition en poids, l’écriture équivalente pour un Poisson (fiche P2, exercice). Le nombre d’arbres est réglé par arrêt anticipé, sur 20 % de l’apprentissage tirés à part : le test n’intervient pas.

from sklearn.ensemble import HistGradientBoostingRegressor

CODES_ZONE = {z: i for i, z in enumerate("ABCDEF")}

def variables(d):
    return np.column_stack([d["age"], d["bonus_malus"], d["puissance"], d["zone"].map(CODES_ZONE)])

gbm = HistGradientBoostingRegressor(
    loss="poisson",
    learning_rate=0.05,
    max_leaf_nodes=15,
    min_samples_leaf=200,       # au moins 200 polices par feuille : pas de feuille sur un cas isolé
    l2_regularization=1.0,
    max_iter=1000,
    early_stopping=True,        # arrêt anticipé sur une validation tirée de l'apprentissage
    validation_fraction=0.2,
    n_iter_no_change=30,
    categorical_features=[3],   # la zone, en catégorie
    random_state=42,
)
gbm.fit(variables(app), app["nb_sinistres"] / app["exposure"], sample_weight=app["exposure"])
for d in (app, tst):
    d["freq_gbm"] = gbm.predict(variables(d))

dev_gbm = deviance_poisson(y_tst, tst["freq_gbm"].to_numpy() * e_tst)
meilleur = int(np.argmax(gbm.validation_score_))   # validation_score_[0] : le modèle constant
print(f"Arbres ajustés avant l'arrêt anticipé : {gbm.n_iter_} (meilleure perte de validation "
      f"après {meilleur} arbres, puis {gbm.n_iter_no_change} sans progrès)")
print(f"Déviance de test : GLM {dev_glm:,.1f}, boosting {dev_gbm:,.1f}")
print(f"Déviance du boosting par rapport au GLM : {100 * (dev_gbm / dev_glm - 1):+.2f} %")
print(f"Gini de test : GLM {gini(tst, 'freq_glm'):.3f}, boosting {gini(tst, 'freq_gbm'):.3f}")
print(f"Sinistres du test : {y_tst.sum()} observés, GLM {(tst['freq_glm'] * e_tst).sum():.1f}, "
      f"boosting {(tst['freq_gbm'] * e_tst).sum():.1f}")

# Le même réglage, avec trois autres tirages de la validation interne
print("\nDéviance de test du boosting selon le tirage de la validation interne :")
for graine in (0, 1, 2):
    autre = HistGradientBoostingRegressor(**{**gbm.get_params(), "random_state": graine})
    autre.fit(variables(app), app["nb_sinistres"] / app["exposure"], sample_weight=app["exposure"])
    print(f"  graine {graine} : {autre.n_iter_} arbres, déviance "

L’arrêt anticipé coupe l’ajustement à 91 arbres : la perte de validation ne baisse plus depuis le 61e, et les 30 suivants sont la patience demandée (n_iter_no_change=30). scikit-learn garde ces 91 arbres pour prédire, sans revenir au meilleur ; XGBoost, plus bas, prédit avec la meilleure itération. Sur le test, le boosting fait un peu moins bien que le GLM : déviance de 5 946,3 contre 5 929,2 (0,29 % de plus), Gini de 0,229 contre 0,239. Il est aussi bien calibré au total (1 209,3 sinistres prédits pour 1 209 observés). Avec trois autres tirages de la validation interne, sa déviance va de 5 942,1 à 5 948,9 : toujours au-dessus du GLM. Le challenger ne gagne pas d’office. Sur 35 000 polices et quatre variables, la structure du GLM (des bandes, des effets multiplicatifs) est déjà une bonne approximation, et le boosting paie en variance ce qu’il gagne en souplesse.

Avec xgboost installé, le même challenger s’écrit ainsi. XGBoost prend l’exposition en offset par base_margin, l’arrêt anticipé se règle sur une validation interne tirée de l’apprentissage, et la prédiction s’arrête à la meilleure itération.

import xgboost as xgb

def variables_xgb(d):
    return pd.get_dummies(d[["age", "bonus_malus", "puissance", "zone"]], columns=["zone"], dtype=float)

interne = np.random.default_rng(7).random(len(app)) < 0.2     # validation interne, jamais le test
X_app, X_tst = variables_xgb(app), variables_xgb(tst)
d_fit = xgb.DMatrix(X_app[~interne], label=app["nb_sinistres"][~interne],
                    base_margin=np.log(app["exposure"][~interne]))
d_val = xgb.DMatrix(X_app[interne], label=app["nb_sinistres"][interne],
                    base_margin=np.log(app["exposure"][interne]))
d_tst = xgb.DMatrix(X_tst[X_app.columns], base_margin=np.log(tst["exposure"]))

params = {"objective": "count:poisson", "eta": 0.05, "max_depth": 4, "min_child_weight": 50,
          "subsample": 0.8, "lambda": 1.0, "tree_method": "hist", "seed": 42}
booster = xgb.train(params, d_fit, num_boost_round=2000, evals=[(d_val, "validation")],
                    early_stopping_rounds=50, verbose_eval=False)
# Avec base_margin, la prédiction est le nombre de sinistres attendu de la police
mu_xgb = booster.predict(d_tst, iteration_range=(0, booster.best_iteration + 1))
print(f"Arbres retenus : {booster.best_iteration + 1}")
print(f"Déviance de test : GLM {dev_glm:,.1f}, XGBoost {deviance_poisson(y_tst, mu_xgb):,.1f}")

def lorenz(d, col):
    d = d.sort_values(col)
    return (np.r_[0, d["exposure"].cumsum() / d["exposure"].sum()],
            np.r_[0, d["nb_sinistres"].cumsum() / d["nb_sinistres"].sum()])

Le boosting prédit plus que le GLM pour les conducteurs de 25 ans ou moins au volant d’un véhicule de puissance 9 à 11 (1,10 chez les 18-21 ans, 1,20 chez les 22-25 ans), et moins pour les mêmes âges avec un véhicule moins puissant (0,91 et 0,87). Ailleurs, les deux modèles s’accordent à 5 % près, sauf les 26-30 ans aux véhicules puissants (1,14). C’est la signature d’une interaction que le GLM n’a pas : l’effet de la puissance n’est pas le même chez les jeunes conducteurs. On l’ajoute au GLM sous la forme la plus simple, une variable « 25 ans ou moins et puissance 9 ou plus ». Sur un vrai portefeuille, on essaierait aussi la frontière de 30 ans que suggère la ligne 26-30.

for d in (app, tst):

glm_inter = smf.glm(formule + " + jeune_puissant", data=app, family=sm.families.Poisson(),

tst["freq_glm_inter"] = glm_inter.predict(tst, offset=np.zeros(len(tst)))
dev_inter = deviance_poisson(y_tst, tst["freq_glm_inter"].to_numpy() * e_tst)

      f"{np.exp(glm_inter.conf_int().loc['jeune_puissant', 1]):.2f})")

reference = contributions(y_tst, tst["freq_glm"].to_numpy() * e_tst)
modeles = {"tarif uniforme": (freq_app * e_tst, "1 paramètre"),
           "GLM de P2": (tst["freq_glm"].to_numpy() * e_tst, f"{len(glm.params)} paramètres"),
           "GLM + interaction": (tst["freq_glm_inter"].to_numpy() * e_tst, f"{len(glm_inter.params)} paramètres"),
           "boosting": (tst["freq_gbm"].to_numpy() * e_tst, f"{gbm.n_iter_} arbres")}
lignes = {}
for nom, (mu, taille) in modeles.items():
    ecarts = contributions(y_tst, mu) - reference
    lignes[nom] = {"taille": taille, "déviance de test": ecarts.sum() + reference.sum(),
                   "écart au GLM de P2": ecarts.sum(),
                   "écart-type de l'écart": np.sqrt(len(ecarts)) * ecarts.std(),
                   "Gini de test": gini(tst.assign(m=mu / e_tst), "m") if np.ptp(mu / e_tst) > 1e-9 else 0.0}
print(pd.DataFrame.from_dict(lignes, orient="index").to_string(float_format=lambda v: f"{v:,.3f}"))

Recommandation type en revue tarifaire : garder le GLM en référence, et utiliser le boosting en détecteur : il montre les interactions que le GLM a oubliées, qu’on ajoute ensuite explicitement à la formule si elles ont un sens métier. On cumule ainsi l’essentiel de la performance et la défendabilité d’une structure à relativités. Les tarifs auto sont libres : l’ACPR ne les homologue pas, elle contrôle a posteriori, et le règlement européen sur l’IA ne classe pas la tarification auto parmi les systèmes à haut risque (l’annexe III, point 5 c, vise l’assurance vie et maladie). La défendabilité se joue donc devant la revue interne et la fonction actuarielle, et dans le dossier que l’on produit en cas de contrôle.

Cas où le boosting peut gagner sa place en production : des portefeuilles très grands, avec beaucoup de variables et des interactions nombreuses qu’on ne peut pas toutes écrire à la main, quand l’organisme accepte d’outiller l’explicabilité et le suivi dans le temps.

Exercice : trouvez l’erreur

La première version de cette fiche n’ajustait pas de GLM : la « référence » était la fréquence moyenne de chaque segment âge × bonus-malus × zone de l’apprentissage, appliquée au test. La sortie affichait :

“Déviance Poisson hors échantillon (baseline) : inf”

et la prose concluait au gain du challenger. D’où vient ce inf, et qu’en conclure ?

Voir la réponse

Un segment sans sinistre en apprentissage reçoit une fréquence prédite nulle. Si une police de ce segment a un sinistre dans le test, la déviance de Poisson contient \(y \log(y / 0)\) : elle est infinie, et tout « gain » calculé contre elle n’a pas de sens. Le bloc ci-dessous le mesure sur ce portefeuille.

segments = app.groupby(["age_bande", "bm_bande", "zone"], observed=True).agg(
    sinistres=("nb_sinistres", "sum"), exposition=("exposure", "sum"))
segments["freq_segment"] = segments["sinistres"] / segments["exposition"]
t = tst.join(segments["freq_segment"], on=["age_bande", "bm_bande", "zone"])
t["freq_segment"] = t["freq_segment"].fillna(freq_app)    # segment absent de l'apprentissage
nuls = t["freq_segment"] == 0
print(f"Segments : {len(segments)}, dont {(segments['sinistres'] == 0).sum()} sans aucun sinistre en apprentissage")
print(f"Polices du test dans ces segments : {nuls.sum()}, sinistres du test qu'elles portent : {t.loc[nuls, 'nb_sinistres'].sum()}")
with np.errstate(divide="ignore", invalid="ignore"):
    print(f"Déviance de test de la moyenne par segment : {deviance_poisson(y_tst, t['freq_segment'].to_numpy() * e_tst):,.1f}")
Segments : 142, dont 26 sans aucun sinistre en apprentissage
Polices du test dans ces segments : 49, sinistres du test qu'elles portent : 7
Déviance de test de la moyenne par segment : inf

142 segments, dont 26 sans aucun sinistre en apprentissage. 49 polices du test tombent dans ces segments et portent 7 sinistres : leur fréquence prédite est nulle, et la déviance de test est infinie. Un seul sinistre dans un segment prédit à zéro suffit. Il n’y a rien à conclure contre une telle référence, et surtout pas le gain du challenger : la sortie disait inf, la prose aurait dû s’arrêter là. La bonne référence est un vrai GLM (étape 2), ou une moyenne par segment lissée vers la moyenne du portefeuille (crédibilité).

Pièges typiques

  • Comparer sans échantillon de test. Évalué sur les données d’apprentissage, le modèle le plus souple paraît le meilleur, parce qu’il a pu apprendre le bruit. Toujours évaluer hors échantillon, sur des polices mises de côté avant tout réglage, et régler les hyperparamètres sur une validation interne ou par validation croisée.
  • Ne pas régulariser le boosting. Taille minimale des feuilles, pénalité, nombre d’arbres réglé par arrêt anticipé : sans eux, il apprend le bruit.
  • Oublier l’exposition dans le boosting. XGBoost la prend en offset par base_margin = log(exposure) ; scikit-learn par la fréquence en cible et l’exposition en poids. Sans, le modèle ajuste des nombres de sinistres par ligne.
  • Prendre une moyenne par segment pour un GLM. Un segment sans sinistre prédit une fréquence nulle et la déviance de test devient infinie (exercice ci-dessus). Un vrai GLM, ou un lissage vers la moyenne, donne une référence qui se compare.
  • Confondre interprétabilité et SHAP. SHAP donne une décomposition de chaque prédiction, pas une relativité globale défendable comme un coefficient de GLM. En revue, c’est un complément, pas un substitut.
  • Recommander le boosting parce qu’il gagne en métrique. La défendabilité commerciale et réglementaire compte autant que la performance. Le LLM aura tendance à privilégier le modèle le plus performant ; il faut lui rappeler les contraintes métier.

Pour aller plus loin

  • LightGBM : alternative à XGBoost, de la même famille que l’estimateur de scikit-learn utilisé ici. Comparer sur votre portefeuille, avec la même discipline de découpage.
  • SHAP pour l’explicabilité locale : pip install shap. Il produit une explication par police, utile en service client, à documenter en complément de la méthodologie globale.
  • Double lift : trier les polices du test par le rapport boosting / GLM, et comparer, par décile de ce rapport, l’observé à chacun des deux modèles. C’est la vue qui dit lequel a raison là où ils divergent.
  • Modèles hybrides GLM-ML : un GLM dont l’offset est la prédiction d’un boosting, ou un boosting sur les résidus du GLM. Demander à Claude : “propose des architectures hybrides GLM et boosting pour ce portefeuille, et ce que chacune coûte en explicabilité”.
