S3. IFRS 17, explication de la CSM

Cette fiche illustre la démarche C avec un effort fort de vulgarisation. Ce que vous apprenez n’est pas la CSM IFRS 17, mais comment traduire une mécanique technique pour un board sans perdre la rigueur, et comment anticiper les questions pour préparer les réponses.

La démarche se pratique en direct dans l’atelier de la demi-journée « Communication et tableaux de bord » du support.

Le contexte métier

La norme IFRS 17, appliquée depuis le 1er janvier 2023, a profondément modifié la comptabilité des contrats d’assurance. La marge sur services contractuels (Contractual Service Margin, CSM) est la composante la plus discutée : c’est le profit attendu d’un groupe de contrats, pas encore reconnu, qui passe en résultat au fil du service rendu.

Pour le board, le directeur financier ou le contrôle de gestion, la CSM est souvent une boîte noire. Le vocabulaire (cohorte, taux verrouillé, accrétion, unités de couverture) décourage la discussion. Le rôle de l’actuaire est de traduire ces mécaniques en langage de management, sans perdre la rigueur.

Ce cas illustre l’organisation des données (cohorte structurée, paramètres traçables), l’interface de présentation (illustration chiffrée, graphique de libération), la gouvernance (distinction entre best estimate, ajustement pour risque, CSM), et le pilotage IA (5 prompts du concept à l’illustration board).

Donnée d’entrée

Cas d’école : une cohorte de 10 000 contrats d’assurance temporaire décès émis en 2026, sur 10 ans, à primes annuelles, sans valeur de rachat. Le produit n’est pas participatif : il relève du modèle général (GMM, General Measurement Model). La mortalité suit une loi de Makeham illustrative, sans valeur réglementaire. L’ajustement pour risque (RA) est calculé par une méthode simple : l’effet d’une mortalité relevée de 10 %.

Le code tire de la loi de Makeham la probabilité de décès dans l’année à l’âge \(x\), avec \(A = 0{,}0002\), \(B = 0{,}00003\) et \(c = 1{,}10\) ; le calcul du RA multiplie ces \(q_x\) par 1,10 :

\[ \mu_x = A + B\,c^x, \qquad q_x = 1 - \exp\!\left(-\int_x^{x+1} \mu_y \,\mathrm{d}y\right) = 1 - \exp\!\left(-A - B\,c^x\,\frac{c - 1}{\ln c}\right). \]

Le bloc ci-dessous est le moteur de la fiche : la cohorte et les fonctions de calcul. Il ne fait qu’une chose, calculer ; les blocs suivants affichent. La fiche C3 réutilise ce même bloc pour sa présentation au board, sans retaper un seul chiffre.

# Moteur de la fiche S3 : cohorte et calcul. La fiche C3 exécute ce bloc tel quel.
import numpy as np
import pandas as pd

COHORTE = {
    "annee_emission": 2026,
    "duree": 10,                          # années de couverture
    "n_contrats": 10_000,
    "age_souscription": 45,
    "capital_deces": 100_000,             # EUR, versé en fin d'année du décès
    "prime_annuelle": 600,                # EUR, payée en début d'année par les contrats en vigueur
    "frais_acquisition_pct_prime": 0.40,  # 40 % de la première prime
    "frais_gestion_par_an": 25,           # EUR par contrat en vigueur
    "taux_rachat": 0.06,                  # résiliations annuelles, sans valeur de rachat
    "makeham": (0.0002, 0.00003, 1.10),   # mu_x = A + B c^x, loi illustrative (pas une table réglementaire)
    "facteur_mortalite": 1.00,            # 1,10 = mortalité best estimate relevée de 10 %
    "taux_verrouille": 0.02,              # taux de la comptabilisation initiale, verrouillé pour la CSM
    "marge_mortalite_ra": 0.10,           # RA : effet d'une mortalité relevée de 10 %
}

def qx(c: dict, choc: float = 0.0) -> np.ndarray:
    """q_x sur la durée du contrat, déduit de la force de mortalité de Makeham."""
    A, B, cc = c["makeham"]
    x = c["age_souscription"] + np.arange(c["duree"])
    integrale_mu = A + B * cc**x * (cc - 1) / np.log(cc)      # intégrale de mu entre x et x+1
    return (1 - np.exp(-integrale_mu)) * c["facteur_mortalite"] * (1 + choc)

def projeter(c: dict, choc_mortalite: float = 0.0, taux: float | None = None,
             depuis: int = 0) -> dict:
    """Flux attendus année par année, et leurs valeurs actuelles vues de l'année `depuis`."""
    taux = c["taux_verrouille"] if taux is None else taux
    n = c["duree"]
    q = qx(c, choc_mortalite)
    en_vigueur = np.zeros(n + 1)
    en_vigueur[0] = c["n_contrats"]
    for t in range(n):
        en_vigueur[t + 1] = en_vigueur[t] * (1 - q[t]) * (1 - c["taux_rachat"])
    l = en_vigueur[:n]                                        # contrats en vigueur en début d'année
    primes = l * c["prime_annuelle"]
    frais = l * c["frais_gestion_par_an"]
    frais[0] += c["n_contrats"] * c["prime_annuelle"] * c["frais_acquisition_pct_prime"]
    deces = l * q * c["capital_deces"]
    t = np.arange(n)
    futur = t >= depuis
    v_debut = (1 + taux) ** -(t - depuis)                     # primes et frais : début d'année
    v_fin = (1 + taux) ** -(t + 1 - depuis)                   # décès : fin d'année
    return {
        "en_vigueur": l, "q": q, "primes": primes, "frais": frais, "deces": deces,
        "va_entrees": (primes * v_debut)[futur].sum(),
        "va_sorties": (frais * v_debut)[futur].sum() + (deces * v_fin)[futur].sum(),
    }

def mesurer(c: dict, taux: float | None = None, depuis: int = 0) -> dict:
    """Best estimate, RA et flux d'exécution ; CSM ou composante de perte à l'émission."""
    central = projeter(c, taux=taux, depuis=depuis)
    choque = projeter(c, choc_mortalite=c["marge_mortalite_ra"], taux=taux, depuis=depuis)
    best_estimate = central["va_sorties"] - central["va_entrees"]
    ra = (choque["va_sorties"] - choque["va_entrees"]) - best_estimate
    flux_execution = best_estimate + ra                       # VA sorties - VA entrées + RA
    return {
        "va_entrees": central["va_entrees"], "va_sorties": central["va_sorties"],
        "best_estimate": best_estimate, "ra": ra, "flux_execution": flux_execution,
        "csm": max(0.0, -flux_execution),                     # jamais négative
        "composante_perte": max(0.0, flux_execution),         # groupe onéreux : perte immédiate
        "projection": central,
    }

def liberer_csm(c: dict, csm_initiale: float) -> pd.DataFrame:
    """Accrétion au taux verrouillé, puis libération au prorata des unités de couverture."""
    unites = projeter(c)["en_vigueur"] * c["capital_deces"]   # capital assuré en vigueur
    r = c["taux_verrouille"]
    lignes, csm = [], csm_initiale
    for t in range(c["duree"]):
        accretion = csm * r
        liberation = (csm + accretion) * unites[t] / unites[t:].sum()
        lignes.append({"annee": c["annee_emission"] + t, "csm_debut": csm, "accretion": accretion,
                       "unites_couverture": unites[t], "liberation": liberation,
                       "csm_fin": csm + accretion - liberation})
        csm = csm + accretion - liberation
    return pd.DataFrame(lignes)

MESURE = mesurer(COHORTE)
LIBERATION = liberer_csm(COHORTE, MESURE["csm"])
import matplotlib.pyplot as plt

m = MESURE
print(f"Cohorte {COHORTE['annee_emission']} : {COHORTE['n_contrats']:,} contrats temporaire décès sur {COHORTE['duree']} ans")
print(f"VA des entrées (primes)            : {m['va_entrees']:>14,.0f} EUR")
print(f"VA des sorties (décès, frais)      : {m['va_sorties']:>14,.0f} EUR")

print(f"CSM initiale = max(0, -flux)       : {m['csm']:>14,.0f} EUR")
print(f"Composante de perte                : {m['composante_perte']:>14,.0f} EUR")

Le point à faire passer au board est la dernière ligne : pour un groupe profitable, le passif à l’émission vaut zéro, parce que la CSM compense exactement le profit attendu. Pour un groupe onéreux, c’est l’inverse : la CSM vaut zéro et la perte attendue passe tout de suite en résultat (composante de perte). La fonction mesurer l’écrit ainsi, avec \(\mathrm{FE}\) les flux d’exécution :

\[ \mathrm{FE} = \mathrm{VA}_{\text{sorties}} - \mathrm{VA}_{\text{entrées}} + \mathrm{RA}, \qquad \mathrm{CSM}_0 = \max(0,\ -\mathrm{FE}), \qquad \text{composante de perte} = \max(0,\ \mathrm{FE}). \]

Les unités de couverture sont le capital assuré en vigueur : c’est la quantité de couverture fournie chaque année (IFRS 17, B119), pas la prestation versée. Chaque année, la CSM (accrétée au taux verrouillé) est libérée au prorata des unités de l’année sur les unités restantes. Comme les décès et les résiliations réduisent le nombre de contrats en vigueur, la libération décroît : de 1,43 M EUR la première année à 0,94 M EUR la dernière. Le total libéré (11,7 M EUR) dépasse la CSM initiale du montant de l’accrétion.

La fonction liberer_csm fait, pour chaque année \(t = 0, \dots, T - 1\) (\(T = 10\), \(t = 0\) en 2026), avec \(r\) le taux verrouillé et \(\mathrm{UC}_t\) le capital assuré en vigueur au début de l’année \(t\) :

\[ \begin{aligned} \text{accrétion}_t &= r\, \mathrm{CSM}_t, \\ \text{libération}_t &= \left(\mathrm{CSM}_t + \text{accrétion}_t\right) \frac{\mathrm{UC}_t}{\sum_{u=t}^{T-1} \mathrm{UC}_u}, \\ \mathrm{CSM}_{t+1} &= \mathrm{CSM}_t + \text{accrétion}_t - \text{libération}_t . \end{aligned} \]

La dernière année, la fraction vaut 1 : toute la CSM restante est libérée.

L’homologue Solvabilité II de l’ajustement pour risque est la marge de risque : les deux rémunèrent l’incertitude, par des méthodes différentes. La CSM, elle, n’a pas d’homologue au passif Solvabilité II : le même profit futur y apparaît directement en fonds propres. Les deux normes coexistent et ne se réconcilient pas trivialement ; c’est un point que le board demande souvent.

Étape 4. Sensibilité au taux d’actualisation

Le prompt 4 pose une question précise : les taux montent de 100 bp dans 5 ans. En modèle général, la réponse est que la CSM ne bouge pas. Les flux d’exécution sont réévalués au taux courant, mais l’effet d’un changement de taux passe en produits ou charges financiers d’assurance (IFRS 17, paragraphes 87 et 88 ; B97 a) : en résultat, ou pour partie en OCI si l’organisme a choisi cette option. La CSM continue d’être accrétée au taux verrouillé.

Exercice : trouvez l’erreur

Une première version de cette fiche portait sur une cohorte d’épargne : 10 000 contrats, prime unique de 5 000 EUR, 600 EUR versés chaque année pendant 10 ans quel que soit l’état de l’assuré, 4 % de frais d’acquisition, 30 EUR de frais de gestion par an, taux de 2 %, RA fixé à 5 % de la valeur absolue du best estimate. Le code calculait :

pvcf_be = (v * flux_par_an).sum()        # flux = entrées - sorties, soit -9 722 091 EUR
ra = abs(pvcf_be) * 0.05                 # 486 105 EUR
csm_initial = -pvcf_be - ra              # affiché : « CSM 9 235 987 EUR (>0, contrat profitable) »

La fiche en tirait une slide board : « CSM positive, cohorte profitable ». Trouvez les erreurs, dans le calcul et dans le choix du produit.

Voir la réponse
  1. Le signe. pvcf_be est calculé comme entrées moins sorties : −9,7 M EUR veut dire que l’assureur paie 9,7 M de plus qu’il ne reçoit (600 EUR par an pendant 10 ans, c’est 6 000 EUR pour 5 000 encaissés). Les flux d’exécution valent sorties moins entrées plus RA, soit +10,2 M EUR : le groupe est onéreux. La CSM vaut zéro et une composante de perte de 10,2 M EUR passe en résultat dès l’émission. La formule -pvcf_be - ra a transformé une perte en profit.
  2. Le produit. Un versement de 600 EUR par an, certain, sans mortalité ni aucun autre aléa lié à l’assuré, ne transfère pas de risque d’assurance significatif. Ce n’est pas un contrat d’assurance au sens d’IFRS 17 (définition de l’annexe A) : il relève d’IFRS 9. Et une épargne en euros avec participation aux bénéfices relèverait de la VFA, pas du modèle général.
  3. Le RA. Un pourcentage fixe du best estimate, sans lien avec un risque non financier identifié, ne se justifie pas au regard du paragraphe 37.

Le bloc ci-dessous refait le calcul avec les bons signes.

v = 1 / 1.02 ** np.arange(10)
va_entrees = 10_000 * 5_000
va_sorties = 10_000 * (600 + 30) * v.sum() + 10_000 * 5_000 * 0.04
best_estimate = va_sorties - va_entrees
ra = 0.05 * abs(best_estimate)
flux_execution = best_estimate + ra
print(f"VA entrées {va_entrees:,.0f} ; VA sorties {va_sorties:,.0f}")
print(f"Flux d'exécution : {flux_execution:,.0f} EUR")
print(f"CSM : {max(0.0, -flux_execution):,.0f} EUR ; composante de perte : {max(0.0, flux_execution):,.0f} EUR")
print(f"Ce qu'affichait la formule fausse : {-(va_entrees - va_sorties) - ra:,.0f} EUR")

La leçon pour la démarche : une CSM « positive, donc profitable » s’accepte seulement après avoir vérifié le sens des flux sur un cas où l’on connaît la réponse. Ici, 6 000 EUR versés pour 5 000 encaissés suffisaient à voir la perte.

Pièges typiques

  • Confondre CSM et profit annuel. La CSM est le stock de profit non reconnu. Le flux annuel libéré en résultat en est une fraction. Toujours distinguer les deux dans la communication.
  • Dire que la CSM « n’absorbe rien ». Elle absorbe les révisions défavorables des hypothèses liées au service futur (IFRS 17, B96) tant qu’elle reste positive ; au-delà, la perte passe en résultat. Elle n’est pas pour autant un capital de solvabilité : c’est un profit différé, pas une ressource pour payer des sinistres.
  • Faire passer les écarts d’expérience dans la CSM. Les écarts de l’année (décès réels contre attendus, frais réels contre attendus) passent en résultat (B97 c). Seules les révisions liées au service futur ajustent la CSM.
  • Présenter le RA comme une « marge de prudence ». Le paragraphe 37 le définit comme la compensation que l’entité exige pour porter l’incertitude due aux risques non financiers. Son homologue Solvabilité II est la marge de risque, pas la CSM.
  • Confondre deux questions de taux. « Les taux montent dans 5 ans » ne change pas la CSM en modèle général ; « la cohorte a été émise à un autre taux » change la CSM initiale. Le prompt 4 pose la première, un LLM répond souvent à la seconde.
  • Demander à Claude une explication IFRS 17 sans cadrer. Vous obtenez un cours académique dont une partie est imprécise. Toujours cadrer : audience board, langage simple, illustration chiffrée, et chaque affirmation technique rattachée à un paragraphe de la norme que vous vérifiez.

Pour aller plus loin

  • Modèle général (GMM), PAA, VFA. Les trois modèles d’IFRS 17. Ce cas illustre le GMM. La PAA (Premium Allocation Approach) est une simplification ouverte notamment aux contrats de couverture d’un an au plus. La VFA (Variable Fee Approach) s’applique aux contrats à participation directe, comme l’épargne en euros.
  • Unités de couverture. Ici le capital assuré en vigueur, non actualisé. D’autres choix sont défendables (actualisation, capital sous risque) : le choix se documente dans la note technique.
  • Modélisation stochastique. Pour les contrats avec options et garanties financières, les flux d’exécution demandent des scénarios stochastiques. Voir lifelib pour des implémentations ouvertes.
  • Couplage IFRS 17 et Solvabilité II. Un projet d’industrialisation type produit les deux à partir d’une source de données unique (atelier du deuxième jour après-midi, « Automatisation et industrialisation »).
  • Évolutions normatives. Suivre les publications de l’IASB et leur adoption dans l’Union européenne, qui rend la norme applicable aux comptes IFRS (pour IFRS 17, le règlement (UE) 2021/2036).
