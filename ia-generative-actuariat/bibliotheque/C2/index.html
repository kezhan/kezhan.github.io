C2. Rapport annuel d’un fonds vie

Cette fiche illustre la démarche D sur un rapport annuel Quarto. Ce que vous apprenez n’est pas la gestion de fonds vie, mais le pattern « source unique de chiffres, template paramétrable, régénération annuelle », applicable à tout livrable périodique, et la relecture des commentaires proposés par Claude contre les sorties.

TipDémarche illustrée : D, construire un dashboard ou un rapport (long format)

La démarche se pratique en direct dans l’atelier de la demi-journée « Communication et tableaux de bord » du support.

Le contexte métier

Le rapport annuel d’un fonds vie épargne présente la composition du portefeuille, la performance, la sinistralité, les marges et les perspectives. Il est largement répétitif d’une année sur l’autre : structure identique, sources de données stables, gabarits de graphiques constants. Seuls les chiffres changent.

Pour l’actuaire qui le produit chaque année, l’enjeu est de rendre la production reproductible. La cible : un document Quarto qui se régénère à partir des données de l’arrêté, avec une intervention humaine sur les parties qualitatives (commentaires, perspectives) et une signature actuarielle qui valide l’ensemble. Le point faible du dispositif, ce sont les commentaires : Claude les rédige vite, et un commentaire peut citer des chiffres qui ne sont pas ceux du tableau juste au-dessus.

Ce cas illustre l’organisation des données (sources tracées, séparation données / template), l’optimisation du code (template Quarto et cellules paramétrées), l’interface de présentation (sections normalisées, graphiques cohérents), la gouvernance (versionnement Git par arrêté, traçabilité des chiffres), et le pilotage IA (5 prompts pour la structure, les graphiques et les commentaires).

Donnée d’entrée

La première cellule porte l’étiquette parameters : avec le moteur Jupyter, c’est là que Quarto injecte les paramètres passés en ligne de commande (voir « Pour aller plus loin »).

Étape 4. Mortalité observée contre table

L’écart relatif \((\text{observé} - \text{attendu}) / \text{attendu}\) ne dit rien seul : 4 % d’écart sur 100 décès attendus et sur 10 000 n’ont pas le même poids. On teste donc chaque tranche. Sous l’hypothèse que la table est juste, le nombre de décès observés suit à peu près une loi de Poisson de moyenne \(E\) : on calcule \(z = (O - E) / \sqrt{E}\) et un intervalle de confiance exact à 95 % du rapport \(O / E\).

def test_mortalite(df):
    o, e = df["deces_observes"], df["deces_attendus_table"]
    out = df[["tranche_age", "deces_observes", "deces_attendus_table"]].copy()
    out["o_sur_e"] = o / e
    out["z"] = (o - e) / np.sqrt(e)
    out["ic95_bas"] = stats.chi2.ppf(0.025, 2 * o) / 2 / e
    out["ic95_haut"] = stats.chi2.ppf(0.975, 2 * o + 2) / 2 / e
    out["significatif"] = out["z"].abs() > 1.96
    return out

total = pd.DataFrame({"tranche_age": ["Ensemble"],
                      "deces_observes": [mortalite_observee["deces_observes"].sum()],
                      "deces_attendus_table": [mortalite_observee["deces_attendus_table"].sum()]})
tests = test_mortalite(pd.concat([mortalite_observee, total], ignore_index=True))
print(tests.round(3).to_string(index=False))

Étape 5. Section qualitative : pattern de rédaction assistée

Pattern de prompt pour la rédaction des sections qualitatives (perspectives, message de la direction, contexte macro) :

“Pour la section ‘Perspectives 2026’ du rapport annuel, propose-moi 3 paragraphes courts. Paragraphe 1 : contexte macro-financier attendu pour 2026 (1 à 2 phrases). Paragraphe 2 : impact sur la gestion d’actifs du fonds (politique de duration, allocation cible). Paragraphe 3 : engagement de l’assureur sur le taux servi. Ton : sobre, factuel, accessible à un assuré non-spécialiste. Pas de jargon technique. Laisse les chiffres prospectifs entre crochets, je les compléterai.”

L’actuaire relit chaque paragraphe et :

  • Remplace les chiffres entre crochets par les valeurs internes, validées.
  • Vérifie l’absence d’engagement contractuel involontaire (“nous garantissons” devient “nous visons”).
  • Adapte le ton au style éditorial de la maison.

Pièges typiques

  • Un commentaire dont les chiffres ne sont pas ceux du tableau. Claude rédige un commentaire fluide et plausible ; les pourcentages peuvent venir d’un regroupement différent, d’une version antérieure ou de nulle part. Injecter les chiffres par le code (étape 2), et relire chaque chiffre restant contre la sortie.
  • Régénérer le rapport sans tracer la source. Si vous régénérez le rapport en 2027 avec les données 2025 et que la source a évolué entre-temps (correction comptable, ré-arrêté), vous obtenez un rapport différent de celui publié en 2025. Figer la donnée source par un hash (parquet et meta.json, comme dans R1) et tagger le dépôt Git à l’arrêté. Un tag ne fige pas les données exclues par le .gitignore : c’est le hash qui les identifie.
  • Mélanger calcul et rédaction. Le rapport mélange chiffres (recalculés automatiquement) et prose (qui demande la signature actuarielle). Séparer les deux : un fichier data_arrete_2025.parquet pour les chiffres, un fichier rapport_annuel_2025.qmd pour la prose qui les utilise.
  • Hallucinations dans les sections qualitatives. Si vous demandez à Claude de rédiger “comme un dirigeant”, il peut inventer des promesses, des chiffres prospectifs, des engagements. Relire et corriger chaque paragraphe.
  • Graphiques non conformes à la charte. Le rapport est public, donc lu et jugé. Définir une palette au début et la maintenir.
  • Oublier la traçabilité des chiffres. Pour un rapport publié, tout chiffre cité doit remonter à sa source (extraction SQL, fichier d’export, signature). Un fichier audit_trail.json qui liste pour chaque chiffre sa source et son hash est une bonne pratique.

Composition.

  1. Les trois pourcentages sont faux : les obligations font 74,5 % de l’encours, pas 88 % ; les actions 14,9 %, pas 16 % ; le haut rendement 3,2 %, pas 4 %. Aucun regroupement cohérent ne donne 88 % : les obligations font 74,5 %, et 76,9 % avec le monétaire.
  2. « Ce qui correspond à la duration du passif de 12,3 ans » : la duration de l’actif est de 7,8 ans, 4,5 ans de moins que le passif. Le commentaire présente comme un adossement ce qui est un écart à signaler.
  3. « Volontairement », « stratégie ALM » : des intentions que la source ne contient pas.

Performance.

  1. Taux servi − TMG n’est pas la marge de l’assureur : c’est la participation distribuée aux assurés au-delà de la garantie (1,90 point en 2025). La marge financière se lit entre le rendement comptable et le taux servi net (0,65 point en 2025, chargements de gestion sur encours compris, avant une éventuelle dotation à la PPB, absente de la source).
  2. Le −2,4 % de 2022 est un rendement en valeur de marché ; le taux servi repose sur le rendement comptable (2,35 % en 2022). Les comparer n’a pas de sens.
  3. « Préservé grâce à la provision » : aucune reprise de PPB ne figure dans la source. L’affirmation est peut-être vraie, elle n’est pas démontrée.

Mortalité.

  1. Un seuil de 5 % sur l’écart relatif n’est pas un test de signification. Le \(z\) de Poisson reste entre 0,38 et 0,65 par tranche : la conclusion « pas d’écart significatif » tient, mais pour une autre raison que celle donnée.
  2. « Surmortalité sur 60-69 et 80-89 » : les cinq tranches sont en légère surmortalité, et la plus forte en relatif est 50-59 (\(O / E = 1{,}044\)).

Les plus dangereuses sont celles qui ont l’air justes : un pourcentage proche de la vérité (16 % pour 14,9 %), un vocabulaire actuariel correct sur une grandeur qui n’est pas la bonne (« marge »), une conclusion juste appuyée sur un faux test. Le commentaire se relit chiffre par chiffre contre la sortie, et « validé par l’actuaire » ne s’écrit qu’après cette relecture.

  • Paramétrer le rapport par année. Avec le moteur Jupyter, Quarto lit les paramètres dans une cellule marquée #| tags: [parameters] (la première cellule de cette fiche), pas dans l’en-tête YAML. quarto render rapport_annuel.qmd -P EXERCICE:2026 insère après cette cellule une cellule qui redéfinit EXERCICE = 2026 avant l’exécution. Sur cette fiche, dont les données sont écrites dans le code et s’arrêtent à 2025, le rendu s’arrête sur une erreur au premier accès à l’année 2026 (la ligne qui affiche le taux servi de l’exercice). Pour que le rapport se régénère, les données doivent être lues depuis la source de l’arrêté (par exemple data_arrete_{EXERCICE}.parquet).
