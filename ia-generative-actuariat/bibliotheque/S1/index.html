S1. Note méthodologique SCR non-vie

Cette fiche illustre la démarche C sur une note méthodologique Solvabilité II. Ce que vous apprenez n’est pas le SCR, mais le schéma « structurer, suggérer, faire critiquer, l’actuaire garde la plume », applicable à tout livrable réglementaire (Solvabilité II, IFRS 17, notice produit, fiche d’impact).

TipDémarche illustrée : C, produire un livrable réglementaire

La démarche se pratique en direct dans l’atelier de la demi-journée « Communication et tableaux de bord » du support.

Le contexte métier

Un organisme qui calcule son SCR (Solvency Capital Requirement) en formule standard documente ce calcul dans une note méthodologique. Pour le module de souscription non-vie, la note décrit les trois sous-modules prévus par l’article 114 du Règlement délégué 2015/35 : primes et réserves, catastrophe, cessation (article 118 ; le marché parle souvent de risque de rachat). Elle expose les hypothèses retenues, les paramètres choisis et les contrôles effectués. C’est un livrable qui engage l’organisme : il est relu et validé selon sa gouvernance, par exemple par la fonction gestion des risques et par le responsable de la fonction actuarielle.

Le gain d’une assistance LLM est dans la structuration assistée, pas dans la rédaction automatique. L’actuaire garde la plume sur ce qui engage sa signature.

Dans la formation, cette fiche porte le corrigé de la note méthodologique faite en direct dans l’atelier du deuxième jour au matin, avec la posture de cet atelier : l’assistant structure et suggère, l’actuaire décide et signe.

Donnée d’entrée

Le calcul du SCR de souscription non-vie est fait par ailleurs (en Python ou dans un autre outil). L’entrée de ce cas est ce calcul : code source, valeurs des paramètres, résultats par sous-module. Pour cette fiche on simule le calcul d’un assureur fictif, avec des simplifications volontaires que l’exercice de fin de fiche vous demande de relever.

Les écarts types et les corrélations entre segments sont ceux du texte initial du Règlement délégué 2015/35 (JO L 12 du 17 janvier 2015, annexe II pour les écarts types, annexe IV pour les corrélations). Le texte a été modifié depuis, notamment par le Règlement délégué 2019/981 : pour une vraie note, on vérifie chaque valeur dans la version consolidée en vigueur.

Le code ci-dessous calcule un écart type combiné par segment \(s\), l’agrège entre segments, puis agrège les sous-modules ; le facteur de diversification géographique est pris à 1 :

\[ \begin{aligned} \sigma_s &= \frac{\sqrt{\sigma_{\mathrm{prem},s}^2 V_{\mathrm{prem},s}^2 + \sigma_{\mathrm{prem},s}\, \sigma_{\mathrm{res},s}\, V_{\mathrm{prem},s} V_{\mathrm{res},s} + \sigma_{\mathrm{res},s}^2 V_{\mathrm{res},s}^2}}{V_s}, \qquad V_s = V_{\mathrm{prem},s} + V_{\mathrm{res},s}, \\ \mathrm{SCR}_{\mathrm{pr}} &= 3 \sqrt{\sum_{s} \sum_{t} \operatorname{corr}(s,t)\, \sigma_s V_s\, \sigma_t V_t}, \\ \mathrm{SCR}_{\text{non-vie}} &= \sqrt{\sum_{k} \sum_{l} \operatorname{Corr}_{\mathrm{NL}}(k,l)\, \mathrm{SCR}_k\, \mathrm{SCR}_l}, \end{aligned} \]

où \(V_{\mathrm{prem},s}\) est la prime nette de l’année, \(V_{\mathrm{res},s}\) la provision, et où \(k\) et \(l\) parcourent les trois sous-modules (primes et réserves, catastrophe, cessation).

import numpy as np
import pandas as pd

# Calcul SCR de souscription non-vie simplifié pour un assureur fictif.
# Montants en euros.
hypotheses = {
    "segments": ["Auto RC", "Auto dommages", "Incendie et dommages aux biens", "RC générale"],
    "segment_annexe_II": [1, 2, 4, 5],
    "primes_nettes": [120e6, 85e6, 62e6, 35e6],     # V_prem : primes nettes de l'année
    "provisions": [310e6, 95e6, 78e6, 145e6],       # V_res, best estimate des sinistres nets
    "sigma_primes": [0.10, 0.08, 0.08, 0.14],       # annexe II, texte initial
    "sigma_reserves": [0.09, 0.08, 0.10, 0.11],     # annexe II, texte initial
    # Corrélations entre segments 1, 2, 4 et 5 : annexe IV, texte initial
    "corr_segments": [[1.00, 0.50, 0.25, 0.50],
                      [0.50, 1.00, 0.25, 0.25],
                      [0.25, 0.25, 1.00, 0.25],
                      [0.50, 0.25, 0.25, 1.00]],
    # Catastrophe : forfait en pourcentage des primes nettes
    "facteur_catastrophe": 0.07,
    # Cessation (article 118) : perte de fonds propres de base si cessent 40 % des
    # contrats dont la cessation augmenterait les provisions techniques. Donnée fictive.
    "perte_cessation_40pct": 4e6,
}

# Corrélations entre sous-modules : article 114
CORR_NL = np.array([[1.00, 0.25, 0.00],     # primes et réserves
                    [0.25, 1.00, 0.00],     # catastrophe
                    [0.00, 0.00, 1.00]])    # cessation

def calcul_scr_souscription_non_vie(h: dict) -> dict:
    primes = np.asarray(h["primes_nettes"], dtype=float)
    provisions = np.asarray(h["provisions"], dtype=float)
    sigma_p = np.asarray(h["sigma_primes"])
    sigma_r = np.asarray(h["sigma_reserves"])
    corr = np.asarray(h["corr_segments"])

    # Volume par segment, facteur de diversification géographique DIV pris à 1
    V = primes + provisions

    # Écart type combiné primes et réserves par segment (article 117)
    sigma_seg = np.sqrt(sigma_p**2 * primes**2
                        + sigma_p * sigma_r * primes * provisions
                        + sigma_r**2 * provisions**2) / V

    # Agrégation entre segments (article 117)
    x = V * sigma_seg
    scr_primes_reserves = 3.0 * np.sqrt(x @ corr @ x)

    scr_catastrophe = h["facteur_catastrophe"] * primes.sum()
    scr_cessation = h["perte_cessation_40pct"]

    sous_modules = np.array([scr_primes_reserves, scr_catastrophe, scr_cessation])
    scr_souscription = np.sqrt(sous_modules @ CORR_NL @ sous_modules)

    return {
        "scr_primes_reserves": scr_primes_reserves,
        "scr_catastrophe": scr_catastrophe,
        "scr_cessation": scr_cessation,
        "scr_souscription_total": scr_souscription,
        "sigma_par_segment": sigma_seg,
        "V_total": V.sum(),
    }

resultats = calcul_scr_souscription_non_vie(hypotheses)
print(f"SCR primes et réserves : {resultats['scr_primes_reserves']:>13,.0f} EUR")
print(f"SCR catastrophe        : {resultats['scr_catastrophe']:>13,.0f} EUR")
print(f"SCR cessation          : {resultats['scr_cessation']:>13,.0f} EUR")
print(f"SCR souscription total : {resultats['scr_souscription_total']:>13,.0f} EUR")
print(f"\nVolume total (primes + provisions) : {resultats['V_total']:,.0f} EUR")
print(f"Ratio SCR / volume : {100*resultats['scr_souscription_total']/resultats['V_total']:.2f} %")

Exercice : trouvez l’erreur

Une première version de cette fiche contenait ces deux lignes :

primes = np.array([120_000_000, 85_000_000, 62_000_000, 35_000_000])
sigma_v = np.sqrt(V @ corr * sigma_combined @ (V * sigma_combined))

La première, exécutée sur un poste Windows, a fait afficher « SCR Premium + Reserve : nan EUR ». La seconde, une fois la première corrigée, donnait un résultat plausible. Qu’est-ce qui ne va pas dans chacune ? Puis, en jouant le contrôleur de l’étape 3, listez les simplifications de la fiche qu’une note devrait signaler.

Voir la réponse
  1. Le débordement. Des entiers Python passés à np.array deviennent des int32 sous Windows avec numpy 1.x. primes**2 dépasse alors \(2^{31}\) et donne des valeurs fausses, parfois négatives, sans message d’erreur ; la racine d’un négatif produit nan. Correction : dtype=float.
  2. L’agrégation. En Python, @ et * ont la même priorité et s’évaluent de gauche à droite. La ligne calcule ((V @ corr) * sigma) @ (V * sigma), soit la somme des \(\operatorname{corr}(s,t)\, V_s V_t\, \sigma_t^2\), et non la somme des \(\operatorname{corr}(s,t)\, \sigma_s V_s\, \sigma_t V_t\) de l’article 117. Correction : x = V * sigma ; np.sqrt(x @ corr @ x).
  3. Un écart faible ne prouve rien. Le bloc ci-dessous compare les écritures. Sur ce portefeuille, la formule fausse ne s’écarte que de moins de 1 % de la bonne : aucun contrôle d’ordre de grandeur ne l’aurait vue. Seule la relecture de la formule contre le texte l’attrape.
V = np.asarray(hypotheses["primes_nettes"]) + np.asarray(hypotheses["provisions"])
sigma = resultats["sigma_par_segment"]
x = V * sigma
corr_annexe = np.asarray(hypotheses["corr_segments"])
corr_uniforme = np.full((4, 4), 0.5) + np.eye(4) * 0.5

print("Carrés calculés en int32 :", np.array([120_000_000, 85_000_000, 62_000_000, 35_000_000], dtype=np.int32) ** 2)
print("Carrés calculés en float :", np.array([120e6, 85e6, 62e6, 35e6]) ** 2)
print()
print(f"Formule juste, corrélations de l'annexe IV    : {3*np.sqrt(x @ corr_annexe @ x):>13,.0f} EUR")
print(f"Formule fausse, corrélations de l'annexe IV   : {3*np.sqrt(V @ corr_annexe * sigma @ (V * sigma)):>13,.0f} EUR")
print(f"Formule juste, matrice uniforme à 0,5         : {3*np.sqrt(x @ corr_uniforme @ x):>13,.0f} EUR")

Les simplifications qu’une note devrait signaler (étape 3) :

  • volume de primes réduit aux primes nettes de l’année, alors que la mesure de volume de l’article 116 compte aussi les primes futures des contrats existants et des contrats à venir ;
  • pas de diversification géographique (DIV pris à 1) ;
  • catastrophe en pourcentage des primes au lieu des scénarios des articles 119 et suivants ;
  • perte en cas de cessation donnée sans son calcul (contrats retenus, modèle de provisions) ;
  • réassurance seulement implicite dans les montants nets, et réassurance non proportionnelle non décrite (elle peut modifier l’écart type de primes, article 117) ;
  • écarts types standard sans discussion des paramètres propres (USP), et repris du texte initial : à vérifier dans la version consolidée.

Pièges typiques

  • Demander à Claude d’écrire la note complète d’un coup. Vous obtenez un document plausible qui contient probablement des références inventées, des chiffres sans calcul, des justifications creuses. Personne ne peut signer ça. Toujours fragmenter : Claude propose la structure, puis des paragraphes section par section que vous validez ou réécrivez.
  • Références inventées ou mal attribuées. Le LLM peut citer un article du Code des assurances ou une recommandation de l’ACPR dont le numéro a l’air juste. Le numéro peut ne pas exister, ou exister avec un autre contenu (la fiche S4 fait trouver une référence inventée glissée parmi des références réelles). Chaque référence se vérifie dans le texte officiel (Légifrance, EUR-Lex, site de l’ACPR) avant d’entrer dans la note.
  • Biais de confirmation. Claude valide spontanément vos choix. Sans le prompt de critique sévère, vous passez à côté de points faibles que le contrôleur, lui, verra. La critique de l’étape 5 n’est pas optionnelle.
  • Oublier les limites. Une note sans section « Limites et points d’attention », ou avec une section complaisante, signale un travail incomplet.
  • Citer des chiffres sans recalcul. Si vous écrivez « Le SCR de souscription total s’élève à X EUR », X vient de la sortie du calcul sur les données à jour, jamais d’une version précédente de la note.

Variantes et cas connexes

  • S2 ORSA, synthèse exécutive : produire la synthèse d’un rapport ORSA pour le conseil d’administration.
  • S3 IFRS 17, explication de la CSM : traduire la CSM IFRS 17 pour un public board, sans noyer dans la technique.
  • S4 Lecture critique d’un texte de l’ACPR : exercice inverse, synthétiser un texte publié pour en sortir les impacts.

Pour aller plus loin

  • L’annexe G de cette formation recense les références ACPR et EIOPA à connaître.
  • Pour des paramètres propres à l’entreprise (USP) au lieu des écarts types standard, voir les articles du Règlement délégué qui les encadrent et les orientations de l’EIOPA sur les USP. Le LLM peut aider à lire les textes et à organiser le dossier, pas à calibrer (la calibration demande les données internes).
