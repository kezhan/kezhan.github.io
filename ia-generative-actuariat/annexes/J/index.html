Annexe J. Formulaire pré-formation

Canevas du formulaire à envoyer aux participants deux à trois semaines avant la formation. Il sert deux objectifs : préparer l’environnement technique, pour que l’installation ne mange pas l’atelier de la première demi-journée, et recueillir les cas du quotidien que chacun veut traiter, auxquels les ateliers s’appliquent aussi bien qu’aux fiches de la bibliothèque. À adapter à l’outil de formulaire du cabinet (Google Forms, Tally, Microsoft Forms, papier).

Format conseillé

  • Envoyer trois semaines avant, pour avoir le temps de relancer.
  • Annoncer dix minutes de remplissage, et s’y tenir : un formulaire court est rempli, un long est abandonné.
  • Préciser que les réponses servent à adapter la formation au groupe et ne sont partagées qu’avec l’animateur, sauf accord explicite.
  • Prévoir un rappel à J-10 et à J-3.

Le formulaire complet

Section 1. Profil professionnel

  1. Nom, prénom, fonction.
  2. Cabinet ou organisme employeur.
  3. Domaine actuariel principal (choix unique) :
    • Tarification non-vie
    • Provisionnement non-vie
    • Vie et prévoyance (provisions mathématiques, projection)
    • Réglementaire (Solvabilité II, IFRS 17, ORSA)
    • Gestion actif-passif et investissement
    • Réassurance
    • Autre (préciser)
  4. Ancienneté actuarielle : moins de 3 ans / 3 à 7 ans / 7 à 15 ans / plus de 15 ans.
  5. Membre de l’Institut des Actuaires : oui (préciser le statut) / non.

Section 2. Environnement technique actuel

  1. Outils utilisés au quotidien (choix multiple) :
    • Excel et VBA
    • R
    • Python
    • SAS
    • Prophet (FIS), Polysystems ou un autre logiciel actuariel
    • SQL
    • Autre
  2. Aisance en Python :
    • Aucune notion
    • Débutant (j’ai suivi un tutoriel, je sais lire un script simple)
    • Intermédiaire (j’écris des scripts avec pandas pour mes analyses)
    • Avancé (je structure mon code en fonctions et en modules)
  3. Avez-vous déjà ouvert un terminal ? Oui / Non / Une fois ou deux, sans bien comprendre.
  4. Utilisez-vous déjà l’IA générative au travail ? (choix multiple) :
    • ChatGPT
    • Claude (claude.ai)
    • Microsoft Copilot ou un autre assistant intégré à la bureautique
    • GitHub Copilot pour le code
    • Un autre assistant (préciser)
    • Aucun
  5. Si oui, à quelle fréquence : quotidienne / hebdomadaire / mensuelle / rare.

Section 3. Préparation du poste

  1. Votre poste pendant la formation sera : un poste professionnel / un poste personnel.
  2. Aurez-vous les droits pour installer un logiciel ? Oui / Non / Je ne sais pas. Si non, demandez dès maintenant à votre DSI d’installer : Python 3.11 ou plus récent, VS Code, Git (Git for Windows sous Windows), l’extension Claude Code de VS Code (identifiant anthropic.claude-code) et, pour le terminal, Claude Code par son installeur natif. La liste et les commandes sont dans l’annexe Installation.
  3. Votre organisme autorise-t-il Claude Code, et sous quelle offre ?
  • Oui, sous une offre entreprise (Team, Enterprise, ou l’API sous contrat)
  • Oui, sous une offre individuelle (Pro, Max)
  • Non, un autre assistant est autorisé (lequel ?)
  • Je ne sais pas
  1. Avez-vous un compte Claude ? Pro / Max / Team / Enterprise / clé d’API / aucun. Un abonnement Pro suffit pour la formation, qui travaille sur des données publiques ou synthétiques.

Section 4. Le cas du quotidien à apporter

Les ateliers de chaque demi-journée s’appliquent à votre cas aussi bien qu’aux fiches de la bibliothèque. Préparé en amont, c’est le cas que vous finirez chez vous la semaine suivante.

  1. Décrivez en cinq à dix lignes un problème actuariel récurrent de votre poste que vous aimeriez traiter avec Claude Code. Exemples :
    • Migrer un classeur Excel-VBA de calcul de provisions mathématiques en module Python.
    • Construire un tableau de bord de suivi de la sinistralité.
    • Rédiger la note méthodologique d’un calcul de SCR.
    • Relire et tester le code Python d’un collègue.
    • Accélérer un Monte Carlo trop lent.
  2. Quelle donnée d’entrée utiliserez-vous ? Un jeu de données public, une donnée synthétique à générer, ou un fichier qui ne contient aucune donnée réelle.
    • Important : aucune donnée réelle, même anonymisée ou pseudonymisée. Pas de données nominatives, pas d’extraction de production. Si votre cas demande des données réelles, apportez leur description (colonnes, types, unités, volumes) : on fabrique en séance, avec l’assistant, un jeu synthétique aux mêmes caractéristiques.
  3. Quelle finalité attendez-vous ? Un module Python testé, une note rédigée, un tableau de bord qui fonctionne, une analyse aboutie.

Section 5. Attentes

  1. Quel résultat concret attendez-vous de ces deux jours ? Trois lignes au plus.
  2. Un point sur lequel vous voulez insister ? Par exemple : la sécurité des données, le réglementaire, la tarification, l’industrialisation.
  3. Des questions à poser à l’animateur avant la formation ?

Ce que le formulaire permet à l’animateur

À partir des réponses, l’animateur peut :

  • Adapter le niveau : un groupe surtout débutant en Python demande plus de temps sur les fondamentaux ; un groupe à l’aise permet d’accélérer.
  • Préparer les cas apportés : les classer par famille (tarification, provisionnement, vie, réglementaire) et les rapprocher des fiches de la bibliothèque.
  • Anticiper les blocages techniques : pour qui ne peut rien installer, prévoir un carnet Google Colab, comme le propose l’atelier de la partie 1 ; pour qui n’a droit qu’à un autre assistant, la même démarche avec cet assistant, sur la même donnée publique.
  • Composer les binômes : associer un participant débutant en Python à un participant plus à l’aise qui travaille sur un sujet voisin.
  • Repérer les attentes hors du périmètre : un cours complet d’apprentissage automatique, par exemple, se recadre en amont ; la formation traite le modèle d’apprentissage comme le challenger d’un GLM (partie 2).

Le mail d’envoi

Il pose le cadre. Modèle :

Bonjour,

En préparation de la formation « Maîtriser l'IA générative pour l'actuariat et l'analyse de données » des [dates], merci de prendre dix minutes pour remplir ce formulaire : [lien]

Vos réponses me permettent d'adapter la formation à votre profil et à vos attentes, et de préparer le cas que vous apporterez : les ateliers s'y appliquent, et plus il est préparé, plus vous repartez avec un travail avancé.

Trois consignes :
1. Décrivez précisément votre cas du quotidien (question 15).
2. N'apportez aucune donnée réelle, même anonymisée : ni données nominatives, ni extraction de production. Si votre cas en demande, décrivez les colonnes, leurs types et leurs unités : vous fabriquerez avec l'assistant des données synthétiques aux mêmes caractéristiques.
3. Si vous n'avez pas les droits d'installation sur votre poste, demandez dès maintenant à votre DSI d'installer Python, VS Code, Git et Claude Code (liste dans l'annexe Installation du support). Sans cette installation, la première demi-journée sera difficile à suivre.

À très bientôt,
[Nom de l'animateur]

Variante pour une formation interne

Pour une formation dans un seul cabinet, on peut ajouter :

  • La connaissance des outils internes (référentiels, bibliothèques maison, bases de données).
  • Les projets en cours qui pourraient servir de cas.
  • La connaissance de la politique IA du cabinet : outils et offres autorisés, données interdites, validations requises.

Les cas pratiques collent alors au contexte réel du cabinet.

TipExercice : relisez cette réponse

À la question 16, un participant répond : « J’apporterai un extrait de notre base sinistres 2025, 5 000 lignes, noms et adresses retirés. Je travaillerai avec mon abonnement Claude Pro. » Que lui répondez-vous ?

Voir la réponse

Ce sont toujours des données réelles. Noms et adresses retirés, chaque ligne reste rattachable à un assuré par les autres colonnes (dates, montants, codes) : ce sont des données pseudonymisées, donc personnelles au sens du RGPD, et une base sinistres peut contenir des données de santé. Tout ce que Claude en lirait partirait chez le fournisseur, et l’offre Pro, grand public, ne fait pas de lui un sous-traitant de son organisme. La consigne de la question 16 vaut sans exception : il décrit les colonnes, leurs types et leurs unités, et fabrique en séance un jeu synthétique aux mêmes caractéristiques.

Pour aller plus loin

  • Les quatre parties du support, une par demi-journée, pour voir où chaque réponse du formulaire sert.
  • La bibliothèque de cas : la liste des fiches peut inspirer un participant qui sèche sur la question 15.
  • L’annexe Installation, à envoyer avec le formulaire.
