Installation et premier pas avec Claude Code

Avant le premier prompt utile, il faut installer Claude Code, se connecter et régler les permissions. Cette annexe est la marche à suivre pratique, celle à laquelle renvoie l’atelier « Un premier échange cadré » (partie 1). Le but n’est pas de devenir expert du terminal : c’est d’avoir un environnement qui marche, qu’on comprend, et dont on sait ce qu’il envoie au fournisseur. Ce qui suit décrit l’état au 29 septembre 2026, d’après la documentation officielle (code.claude.com/docs).

Choisir sa surface

Claude Code se présente sous plusieurs formes, qui partagent le même moteur. Les principales :

Surface Pour qui Avantage principal Limite
Extension VS Code Public sans terminal, débutants Panneau graphique, diff côte à côte, mention de fichiers par @ Demande VS Code
Ligne de commande Utilisateurs à l’aise, automatisation La plus directe Le terminal intimide au début
Application de bureau Qui veut une fenêtre dédiée Séparée de l’éditeur Une application de plus
Web (claude.ai/code) Démonstrations, essais Rien à installer Travaille sur un dépôt GitHub dans un environnement distant : rien de sensible dedans

Il existe aussi une extension pour les éditeurs JetBrains, des applications mobiles et des intégrations (Slack, GitHub Actions) ; la liste à jour est sur code.claude.com/docs.

Recommandation pour un actuaire qui découvre : l’extension VS Code. Le panneau Claude Code s’ouvre à côté de l’éditeur : votre code d’un côté, la conversation de l’autre. Quand Claude propose une modification, vous voyez le diff avant d’accepter.

Si vous êtes à l’aise avec un terminal (PowerShell sous Windows, Terminal sous macOS, un shell sous Linux ou WSL), la ligne de commande offre plus de souplesse pour les travaux scriptés. On y vient avec l’habitude.

Installer

Prérequis :

  • Windows 10 (version 1809) ou plus récent, ou macOS 13 ou plus récent, et 4 Go de mémoire vive.
  • Python 3.11 ou plus récent pour les exercices (vérifier dans un terminal avec python --version).
  • VS Code, version 1.94 ou plus récente pour l’extension.
  • Git, pour les commits (annexe E) ; sous Windows, Git for Windows. Claude Code n’en a pas besoin pour fonctionner : sans Git for Windows, il lance ses commandes par PowerShell ; avec lui, il dispose aussi de Git Bash, mais PowerShell reste par défaut son shell principal. Les règles de permission s’écrivent donc pour les deux, Bash(...) et PowerShell(...), comme dans l’annexe D.
  • Pour l’atelier, de quoi ouvrir un carnet Jupyter : l’extension Jupyter de VS Code, ou Google Colab pour qui ne peut rien installer.
  • Une connexion internet : Claude Code interroge le modèle chez le fournisseur à chaque échange. Tout ce qu’il lit ou affiche part donc chez le fournisseur.

L’extension VS Code, pour démarrer :

  1. Ouvrir VS Code, aller dans l’onglet Extensions (l’icône faite de carrés, à gauche).
  2. Chercher « Claude Code » et installer l’extension officielle d’Anthropic, d’identifiant anthropic.claude-code.
  3. Recharger VS Code si demandé.
  4. L’icône de Claude apparaît dans la barre latérale.

L’extension embarque ce qu’il faut pour son panneau. Pour taper claude dans un terminal, on installe en plus la ligne de commande.

La ligne de commande, par l’installeur natif :

  • Sous Windows, dans PowerShell : irm https://claude.ai/install.ps1 | iex
  • Sous macOS, Linux ou WSL, dans un terminal : curl -fsSL https://claude.ai/install.sh | bash

Ces commandes téléchargent et exécutent un script d’installation : sur un poste d’entreprise, elles peuvent être bloquées, et c’est une question pour votre service informatique. D’autres voies existent (WinGet, Homebrew, les gestionnaires de paquets de Linux, et npm, qui demande Node.js 22 ou plus récent), mais l’installeur natif est la voie que documente Anthropic (code.claude.com/docs/en/setup).

Point de vérification : dans VS Code, le panneau Claude Code affiche une zone de saisie et un bouton pour se connecter. Dans un terminal, claude --version affiche un numéro de version.

Se connecter, et choisir son offre

Claude Code n’est pas disponible dans l’offre gratuite ; il est inclus dans tous les plans payants. Au 29 septembre 2026, en dollars hors taxes (claude.com/pricing) :

Offre Prix Nature
Pro 20 $ par mois (17 $ en annuel) Grand public, usage individuel : la formation
Max 100 $ ou 200 $ par mois Grand public, usage individuel intensif
Team Siège Standard 25 $ par mois (20 $ en annuel), Premium 125 $ (100 $) Entreprise
Enterprise Siège, plus l’usage au tarif de l’API Entreprise, grandes organisations
API (Console, platform.claude.com) Au token Entreprise avec contrat ; suivi fin des coûts par projet ou par utilisateur

Côté API, la documentation d’Anthropic (« Manage costs », code.claude.com/docs/en/costs) donne un coût moyen d’environ 13 $ par développeur et par jour actif, 150 à 250 $ par développeur et par mois, et moins de 30 $ par jour actif pour 90 % des utilisateurs. C’est l’ordre de grandeur à inscrire au budget si l’équipe passe par l’API.

Se connecter. Dans l’extension, le bouton de connexion ouvre le navigateur. Dans un terminal, claude propose de se connecter avec un compte Claude (Pro, Max, Team, Enterprise) ou un compte de la Console (API). Si votre organisme passe par un fournisseur cloud (AWS Bedrock, Google Vertex AI), votre service informatique donne la configuration.

La question qui décide : les données. Tout ce que Claude lit ou affiche part chez le fournisseur. Les offres grand public (Pro, Max) et les offres entreprise (Team, Enterprise, API avec contrat de traitement des données) ne se valent pas : seule une offre entreprise fait du fournisseur un sous-traitant de votre organisme au sens du RGPD. Pour la formation, un abonnement Pro suffit, parce qu’on travaille sur des données synthétiques ou publiques. Pour le travail du cabinet, l’offre se choisit avec la DSI et le délégué à la protection des données, avant le premier fichier réel (annexe G).

NoteSi votre organisme n’autorise pas Claude Code

La démarche de la formation ne dépend pas de l’outil. Avec l’assistant que votre organisme autorise (un assistant d’entreprise, un Copilot sous contrat, un modèle interne), ou dans Google Colab, vous gardez les mêmes gestes : intention avant code, petits pas, chiffres produits par un code exécuté, relecture des sorties, commits. Vous perdez l’exécution automatique : vous copiez le code, vous l’exécutez, vous recollez la sortie, comme au niveau 1 du cadrage (chapitre « Pas toujours besoin d’un modèle de langue », partie 1). Et les données restent synthétiques ou publiques.

Premier dialogue : un essai sur un fichier synthétique

Le premier prompt sert à vérifier que tout marche, sur un fichier synthétique ou public, jamais sur un extrait de votre base de production.

Ouvrez un dossier de travail vide dans VS Code. Pour ce premier essai, passez en mode Manuel : dans VS Code, cliquez sur l’indicateur de mode, sous la zone de saisie, et choisissez Manual (dans un terminal, c’est Shift+Tab ; voir la section suivante). Vous verrez chaque demande d’autorisation. Il faut d’abord un fichier ; le faire créer par Claude garantit qu’il est synthétique. Dans le panneau Claude Code, tapez :

“Crée dans ce dossier un fichier portefeuille_auto.csv : un portefeuille auto synthétique de 1 000 polices, avec un identifiant, l’âge du conducteur, le coefficient de bonus-malus, la région, l’exposition en années et la prime annuelle. Montre-moi le script avant de l’exécuter.”

Puis, une fois le fichier créé :

“Lis portefeuille_auto.csv, donne-moi le nombre de polices, la répartition par tranche de bonus-malus, et la prime annuelle moyenne par région. Si tu manques d’information sur la structure du fichier, demande-moi avant de te lancer.”

Vous devriez voir Claude :

  1. Lire le fichier : dans le dossier du projet, la lecture ne demande pas d’accord. Ce qu’il lit part chez le fournisseur.
  2. Examiner le contenu, repérer les colonnes.
  3. Proposer un script Python avec pandas.
  4. Demander l’autorisation de l’exécuter, sauf si vos permissions l’y autorisent déjà.
  5. Rendre les chiffres demandés, en tableau ou en liste.

Si tout fonctionne, vous êtes prêt. Sinon, vérifiez la connexion au compte et l’accès au réseau. L’atelier poursuit sur freMTPL2freq, un portefeuille public de responsabilité civile automobile.

Les permissions : modes et règles

Claude Code décide de ce qu’il fait seul selon un mode et des règles.

Les modes. En mode Manuel (default), il lit librement dans le dossier du projet, lance sans demander les commandes de pure lecture (ls, cat, git status), et demande votre accord avant de modifier un fichier ou de lancer toute autre commande. acceptEdits accepte en plus les modifications de fichiers ; plan lit et propose sans rien modifier ; auto confie l’examen de chaque action à un second modèle, qui laisse passer ce qu’il juge conforme à votre demande et bloque le reste, sans vous poser la question. Depuis la version 2.1.283, auto est le mode de départ par défaut dans le terminal et dans VS Code ; un administrateur peut le désactiver. En cours de session, on change de mode par l’indicateur de mode sous la zone de saisie dans VS Code, par Shift+Tab dans un terminal. Au début, travaillez en mode Manuel : vous voyez chaque demande, et c’est ainsi qu’on apprend ce que fait l’outil. Pour démarrer chaque session en mode Manuel, ajoutez à vos réglages personnels (~/.claude/settings.json) ce qui suit ; dans VS Code, le dernier mode choisi dans l’indicateur passe avant ce réglage.

{
  "permissions": {
    "defaultMode": "default"
  }
}

Les règles. Le fichier .claude/settings.json du projet autorise, fait demander ou interdit des familles de commandes une fois pour toutes. Il existe à quatre niveaux : les réglages imposés par la DSI (managed-settings.json, qui priment sur tout), vos réglages personnels (~/.claude/settings.json, où ~ désigne votre dossier personnel, C:\Users\<vous> sous Windows), ceux du projet (.claude/settings.json, versionné) et ceux du projet sur votre seul poste (.claude/settings.local.json).

Un point de départ. Créez à la racine du projet un dossier .claude, et dedans le fichier settings.json (ou demandez à Claude de le créer) :

{
  "permissions": {
    "allow": [
      "Bash(python *)",
      "Bash(pytest *)",
      "Bash(git add *)",
      "Bash(git commit *)"
    ],
    "ask": [
      "Bash(git push *)"
    ],
    "deny": [
      "Bash(rm *)",
      "Bash(curl *)",
      "Bash(wget *)",
      "Bash(ssh *)"
    ]
  }
}

Lecture en clair : Claude lance n’importe quel script Python, lance pytest et fait des commits sans demander. Il demande toujours avant un git push, même en mode auto. Il ne supprime pas par rm, n’appelle pas le réseau par curl ou wget, ne se connecte pas à une autre machine par ssh. Pour tout le reste, c’est le mode qui décide : en Manuel il demande, en auto le second modèle tranche. La forme documentée est Bash(python *) ; l’ancienne écriture Bash(python:*) reste acceptée et veut dire la même chose. Ces règles visent l’outil Bash. Avec Git for Windows, des réglages qui portent un deny Bash(...) et aucune règle PowerShell(...) coupent l’outil PowerShell : Claude passe alors par Git Bash, et ces règles s’appliquent. Sans Git for Windows, Claude n’a que PowerShell, qui a ses propres règles (PowerShell(Remove-Item *)) : Bash(rm *) n’y couvre pas Remove-Item, et ce fichier n’arrête rien. La version complète, pour les deux, est en annexe D.

TipExercice : trouvez l’erreur

Cherchez avant de lire la section suivante. Un collègue a ajouté à ce fichier la règle "Read(./data/clients_nominatifs/**)" dans deny, en gardant "Bash(python *)" dans allow. Il explique à son équipe : « Claude ne pourra pas lire ces fichiers, même si on le lui demande. Nos données d’assurés sont protégées, on peut les laisser dans le dossier du projet. » Qu’est-ce qui ne va pas ?

Voir la réponse

La règle deny sur Read empêche l’outil de lecture de Claude Code, et les commandes de lecture qu’il reconnaît (cat, head, tail…), d’ouvrir ces fichiers. Elle n’empêche pas un script Python d’ouvrir le fichier lui-même, comme la documentation des permissions le précise. Or Bash(python *) autorise n’importe quel script Python, par exemple :

import pandas as pd
print(pd.read_csv("data/clients_nominatifs/assures.csv").head())

Claude peut écrire ce script, le lancer sans demander, et lire la sortie : les cinq premières lignes du fichier partent alors chez le fournisseur. Les permissions évitent les accidents ; elles ne protègent pas des données. La seule barrière au niveau du système est le bac à sable de Claude Code, qui n’existe pas sous Windows natif. La bonne réponse est de sortir les données nominatives du dossier de travail.

Ce qui protège vraiment

  • Les permissions évitent les accidents, elles ne protègent pas des données. Une règle deny sur un dossier n’arrête pas un script Python autorisé qui l’ouvre.
  • La seule barrière au niveau du système est le bac à sable (réglage sandbox), qui restreint ce que les commandes et les programmes qu’elles lancent peuvent lire, écrire et joindre. Il fonctionne sous macOS, Linux et WSL2, pas sous Windows natif, et par défaut il laisse la lecture ouverte sur toute la machine : il faut le configurer (annexe D).
  • Les données sensibles restent hors du dossier de travail. On travaille sur des données synthétiques ou pseudonymisées, ou sur des agrégats produits en dehors de la session.
  • Tout ce que Claude lit ou affiche part chez le fournisseur : le contenu d’un fichier ouvert, la sortie d’un script, un head sur un CSV.
  • L’offre compte : seule une offre entreprise (Team, Enterprise, API avec contrat) fait du fournisseur un sous-traitant au sens du RGPD.

Lire ce que Claude exécute : les commandes à reconnaître

Inutile de devenir développeur ; il suffit de reconnaître ce que fait Claude quand il lance une commande. Sans Git for Windows, il passe par PowerShell : la deuxième colonne donne l’équivalent.

Commande (bash) Équivalent PowerShell Ce qu’elle fait Anodine quand Vigilance quand
ls Get-ChildItem (alias ls, dir) Lister les fichiers d’un dossier Toujours Jamais
cd Set-Location (alias cd) Changer de dossier de travail Dans votre projet Claude sort de votre projet
cat fichier.csv Get-Content fichier.csv (alias cat) Afficher le contenu d’un fichier Sur un fichier de code ou synthétique Sur des données réelles, dont le contenu part chez le fournisseur ; ou suivie d’une redirection >, qui écrit un fichier
python script.py python script.py Exécuter un script Python Le script est dans votre projet et vous savez ce qu’il fait Le script appelle le réseau, lit hors du projet ou écrit ailleurs
git commit -m "message" identique Figer une version dans Git Toujours souhaitable Jamais

Les motifs à signaler : rm -rf (en PowerShell, Remove-Item -Recurse -Force), une redirection vers / ou ~/, sudo (en PowerShell, une élévation en administrateur), chmod 777, un git push --force. Devant l’un d’eux, refusez et demandez à Claude pourquoi il en a besoin.

Astuce : demander la traduction en langage naturel

Quand Claude lance une commande longue et illisible (par exemple find . -name "*.py" | xargs grep -l "chainladder" | head -5), répondez simplement :

“Reformule en français ce que tu viens de faire, et pourquoi.”

Claude répond en clair. Cela ne coûte qu’un échange, et c’est ainsi qu’on apprend à lire l’outil. Faites-le systématiquement au début : les motifs reviennent, et vous finissez par les reconnaître sans demander.

TipExercice : accepter ou refuser ?

Sous Windows sans Git for Windows, en mode Manuel, Claude vous demande l’autorisation pour chacune de ces commandes. Lesquelles acceptez-vous, lesquelles refusez-vous ou questionnez-vous ?

  1. Get-ChildItem .\sorties
  2. python -m pytest tests
  3. Get-Content .\donnees\extraction_production.csv -TotalCount 20
  4. Remove-Item -Recurse -Force .\sorties
  5. git push --force origin main
Voir la réponse
  1. Accepter : elle liste le contenu d’un dossier.
  2. Accepter : elle lance les tests du projet.
  3. Refuser : elle affiche les vingt premières lignes d’une extraction de production, qui partent chez le fournisseur. La vraie question est ailleurs : ce fichier n’a rien à faire dans le dossier de travail.
  4. Questionner : elle supprime le dossier et tout ce qu’il contient, sans corbeille. Demandez pourquoi, et vérifiez que ce qui s’y trouve est régénérable ou commité.
  5. Refuser : elle écrase l’historique du dépôt distant, y compris le travail de vos collègues.
